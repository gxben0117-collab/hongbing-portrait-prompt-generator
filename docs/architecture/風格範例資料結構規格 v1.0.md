# 風格範例資料結構規格 v1.0

日期：2026-05-22

## 目的

這份文件定義 `核心資料/風格範例.md` 在本專案中的正式定位、欄位語意、資料分層與未來新增規則。

目標不是把 `風格範例.md` 直接當成 prompt 輸出結果，而是把它定義成：

- 可讀的人類素材母庫
- 可審核的風格資料來源
- 可映射到 runtime 結構的中介層

## 資料角色分層

本專案的風格資料應分成三層理解：

1. `核心資料/核心咒語規範.md`
   - 身份保留與安全限制的最高規範
   - 不負責保存單張風格卡內容

2. `核心資料/風格範例.md`
   - 風格母庫
   - 保存人工整理、策展後、可讀性高的風格卡資料
   - 不應直接等同於 runtime 真實資料

3. `index.html` 內 `CATS`
   - 目前前台實際使用的 runtime 資料
   - 欄位必須短、穩定、可直接被 prompt engine 使用

結論：

`風格範例.md` 是 source library，不是唯一執行來源。

## 當前 md 結構

`風格範例.md` 目前採用：

- 分類層：`## 類別（N 組）`
- 卡片層：`### 名稱 · 副標`
- 欄位層：
  - `ID`
  - `妝容`
  - `角色氛圍`
  - `場景背景`
  - `光線`
  - `服裝`
  - `道具`
  - `特效`
  - `色調`
  - `構圖`
  - `品質`

這個格式適合人類閱讀、策展與比對，但不適合直接作為程式唯一真實來源。

## 正式欄位語意

### 人類可讀欄位

- `角色氛圍`
  - 描述角色存在感、敘事情境、情緒調性
  - 不應直接當成 runtime 的 `char`

- `場景背景`
  - 描述世界觀、地點、時空、環境線索
  - 可映射為 runtime `scene`

- `光線`
  - 描述美術方向與攝影氛圍
  - 目前可作為補充資料，不一定直接進 runtime

- `服裝`
  - 描述服裝、材質、頭飾、配件邏輯
  - 可映射為 runtime `outfit`

- `道具`
  - 不只是道具本體
  - 也代表手部狀態、動作、互動方式
  - 可映射為 runtime `prop`

- `特效`
  - 描述環境粒子、煙霧、水光、布料運動、氛圍效果
  - 屬於高風險欄位，必須經 sanitize

- `色調`
  - 描述整體調色方向
  - 可作為 style 補充，不應覆蓋 identity-first 核心

- `構圖`
  - 描述鏡頭距離、主體比例、環境關係、視覺重心
  - 可映射為 runtime `comp`

- `鏡頭角度`
  - 描述本張風格卡的安全拍攝角度與主體尺度
  - 可映射為 runtime `ang`
  - 不等於一律鎖臉微側；可依情景使用 `sanfen`、`zheng`、`banshen`、`quan`、`huanjing`
  - 共同底線是臉部可讀、頭頸肩連接自然、身體姿勢配合頭臉方向

- `圖片比例`
  - 描述輸出比例與平台/構圖目的
  - 可映射為 runtime `ratio`
  - 近景與半身優先 `r_34`，全身服裝與角色姿勢優先 `r_23`，旅拍地點感優先 `r_916`，大自然或宏觀環境可用 `r_169`

- `鏡頭焦段`
  - 描述安全焦段策略
  - 可映射為 runtime `lens`
  - 全身/古裝/旅拍優先 `l_50`，平衡寫真優先 `l_70`，角色近景可用 `l_80`，半身或特寫才用 `l_85`

- `燈光風格`
  - 描述攝影燈光語法
  - 可映射為 runtime `light`
  - 戲劇光與暗光必須保留臉部主光，不可讓陰影吞掉五官

- `整體氛圍`
  - 描述清透、輕霧、暖光、暗黑等整體環境感
  - 可映射為 runtime `atm`
  - 霧、煙、粒子與暗部只能支援場景，不可遮眼鼻嘴、下顎線或身體輪廓

- `鏡頭語言`
  - 描述整體攝影敘事方式
  - 可映射為 runtime `camLang`
  - 可依情景使用時尚大片、雜誌封面或社群美圖，但不得使用 movie trailer、仰拍英雄鏡頭、背對回眸等高風險語言

- `品質`
  - 描述輸出完成度與細節方向
  - 屬於 style 補充層

### runtime 最小欄位

目前工程上，一張可安全使用的正式卡片，最少應具備：

- `id`
- `name`
- `sub`
- `icon`
- `scene`
- `outfit`
- `prop`
- `comp`

可選補充：

- `mk`
- `ang`
- `ratio`
- `lens`
- `light`
- `atm`
- `camLang`

## 正式映射規則

`風格範例.md` 不應整段原文直接貼入 prompt。

建議的欄位映射如下：

- `場景背景` → `scene`
- `服裝` → `outfit`
- `道具` → `prop`
- `構圖` → `comp`
- `妝容` → `mk`
- `鏡頭角度` → `ang`
- `圖片比例` → `ratio`
- `鏡頭焦段` → `lens`
- `燈光風格` → `light`
- `整體氛圍` → `atm`
- `鏡頭語言` → `camLang`

以下欄位不可直接裸進 runtime：

- `角色氛圍`
- `光線`
- `特效`
- `色調`
- `品質`

它們應先經過：

1. 規範審核
2. 詞彙降風險
3. 必要時轉寫為安全版 runtime 文句

## identity-first 限制

新增風格資料時，必須遵守以下原則：

1. `角色氛圍` 不得用 archetype 取代真人身份
   - 避免：`heroine`、`beauty`、`goddess face`、`flawless actress-like`

2. `場景背景` 可以強，但不能暗示換臉
   - 可保留世界觀
   - 不可夾帶人物模板描述

3. `道具` 與 `構圖` 必須優先服從臉身一致性
   - 不可預設高難度扭轉
   - 不可預設遮臉
   - 不可預設背對

4. `特效` 不可遮蔽五官
   - 不可讓髮飾、煙、紗、粒子、手勢蓋住眼鼻嘴與下顎線

5. `品質` 不可重新導向 AI 美女模板
   - 避免：`perfect beauty`、`porcelain skin`、`luxury beauty reconstruction`

## 鏡頭設計推演原則

每張 `風格範例.md` 卡片都應先依「範例名稱、場景背景、動作與鏡頭、構圖」推演鏡頭設計，而不是套用單一分類預設。

推演順序：

1. 判斷主體尺度
   - close-up / 凝視 / 眼神 / medium close-up → 半身、`r_34`、`l_85`
   - full-body / wide shot / 長裙 / 王座 / 大場景 → 全身、`r_23`、`l_50`
   - 旅拍 / 地標 / 街道 / 山海 → 環境人像、`r_916`、`l_50`

2. 判斷光線與氛圍
   - underworld / gothic / abyss / night / candle → `ls_cinematic` + `at_moody`
   - palace / court / bridal / warm interior → `ls_studio` 或 `ls_golden` + `at_warm`
   - outdoor / travel / lifestyle → `ls_natural` + `at_clear`

3. 判斷鏡頭語言
   - 服裝線條、時尚、角色感 → `cl_fashion`
   - 王座、權力、封面、主體清楚 → `cl_magazine`
   - 生活與旅拍自然互動 → `cl_social` 或 `cl_magazine`

4. 套用身份安全修正
   - 如果動作會造成回眸、背對、仰拍、側臉過大，改寫成 face-readable 的微轉、全身或環境人像
   - 如果焦段和構圖衝突，以頭身比例與臉部辨識優先；全身不得硬用 85mm
   - 如果光影與氛圍會遮臉，降低戲劇性並保留臉部主光

- `source_type`

這些欄位不一定要直接顯示在 md 內，但應該在未來可被腳本管理。

## 舊資料與新資料的分界

目前 `風格範例.md` 內存在不同世代資料混雜：

- 舊資料常見：
  - `heroine`
  - `女神化`
  - `仰拍`
  - `超廣角`
  - `人物渺小`
  - `UE5 cinematic`

- 新資料趨勢：
  - 已較接近身份鎖定、安全動作、可讀臉部、自然比例主線

因此建議把資料視為兩群：

1. `legacy`
   - 保留參考價值
   - 不自動進主流程

2. `approved`
   - 經過核心規範與 sanitize 思路審核
   - 可映射進 runtime

## 新增資料最低標準

未來新增一張風格卡，最低要求：

- 有清楚分類
- 有不重複的 `name + sub`
- 有 `scene`
- 有 `outfit`
- 有 `prop`
- 有 `comp`
- 不含已知高風險詞
- 不與現有庫高重複

理想完整要求：

- `scene`
- `outfit`
- `prop`
- `comp`
- `mk`
- 可選的安全 style 補充欄

## 審核流程建議

未來新增資料，建議流程固定為：

1. 先讀 `核心資料/核心咒語規範.md`
2. 擬定新卡文案
3. 做重複度檢查
4. 做高風險詞檢查
5. 轉成 runtime 需要的最小欄位
6. 再由程式輸出時做第二層 sanitize

## 最終原則

`風格範例.md` 的責任是：

- 保存題材
- 保存靈感
- 保存世界觀與造型方向

它不應直接承擔：

- 身份保留
- 姿勢安全
- 比例安全
- 反 AI 美女模板

這些責任必須回到核心規範與 prompt engine。
