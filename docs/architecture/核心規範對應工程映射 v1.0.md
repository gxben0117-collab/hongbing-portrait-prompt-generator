# 核心規範對應工程映射 v1.0

日期：2026-05-22

## 目的

這份文件用來說明：

- `核心資料/核心咒語規範.md` 的高層原則
- 如何對應到目前實際工程
- 哪些規範已落地
- 哪些規範仍屬理念層或待補強

本文件不修改核心規範本體，只做工程映射。

## 文件角色

三份文件分工如下：

1. `核心資料/核心咒語規範.md`
   - 核心憲法
   - 定義不可違反的身份與安全原則

2. `docs/architecture/Identity-First Prompt 架構規格.md`
   - prompt engine 的正式模組順序
   - 系統設計層規格

3. 本文件
   - 核心規範與實作之間的對照表

## 一個重要現況

`核心資料/核心咒語規範.md` 內目前寫的 prompt flow 為：

`environment → lighting → subject → outfit → action → camera → finish`

但現行程式已實作為 identity-first 順序：

1. `CORE_GATE`
2. `face anchor`
3. `Avoid: ...`
4. `CORE_IDENTITY`
5. `CORE_FACE_BODY_COHERENCE`
6. `CORE_PROPORTION`
7. `CORE_MAKEUP_SAFETY`
8. `CORE_ELASTICITY`
9. `CORE_ANTI_AI`
10. `CORE_ANATOMY`
11. `CORE_REALISM`
12. style / scene / camera 等可變模組

結論：

核心規範檔偏高層理念；實際執行順序以現行 engine 為準。

## 核心規範對照表

### 1. MANDATORY FIRST STEP

核心規範要求：

- 先確認使用者有提供參考照
- 沒有照片就不能進行

工程對應：

- 目前屬於操作規則與使用者流程規則
- 不在前端程式內硬性檢查
- 主要由使用說明、AI 工作流程與操作共識承擔

狀態：

- `部分落地`

建議：

- 若未來要更嚴格，可在 UI 加入提示文字或 checkbox
- 但不建議在本地 HTML 先做過重阻擋

### 2. IDENTITY & EXPRESSION PRESERVATION

核心規範要求：

- 參考照是唯一身份來源
- 保留五官、比例、皮膚、年齡感、自然表情

工程對應：

- `CORE_GATE`
- `CORE_IDENTITY`
- `buildFaceAnchor(faceDesc)`
- `IDENTITY_LOCK`

落地方式：

- prompt 前段固定插入身份保留指令
- `faceDesc` 可把使用者手動描述插入第 2 段
- `Avoid:` 被前移，避免尾段權重流失

狀態：

- `已落地`

### 3. MAKEUP AS SURFACE ONLY

核心規範要求：

- 妝容只能是表面風格
- 不可改眼型、改唇形、重塑臉

工程對應：

- `CORE_MAKEUP_SAFETY`
- 妝容庫 `MK`
- `sanitizePromptText()`

落地方式：

- 妝容描述被限制為 surface cosmetics
- 高風險眼妝詞會被 safer replacement 替換

狀態：

- `已落地`

### 4. IDENTITY ELASTICITY

核心規範要求：

- 允許自然髮流、環境互動、情緒變化、攝影不完美
- 但不可失去可辨識身份

工程對應：

- `CORE_ELASTICITY`
- `CORE_REALISM`

落地方式：

- 允許自然動作、風、衣料、生活感
- 但不允許用彈性當藉口去換臉或扭壞身體

狀態：

- `已落地`

### 5. PROMPT GENERATION RESTRAINTS

核心規範要求：

- 避免 influencer face、plastic skin、AI beauty aesthetics

工程對應：

- `CORE_ANTI_AI`
- `CORE_BEAUTY_SAFETY`
- `sanitizePromptText()`
- `sanitizeCreativeField()`

落地方式：

- 在 prompt 核心層明確壓制 AI 美女模板
- 在資料輸出前再做一次詞彙清洗

狀態：

- `已落地`

### 6. ANATOMY & VISUAL FRAME

核心規範要求：

- 維持成人解剖正確
- 五官可讀
- 可允許部分自然遮擋，但不可破壞辨識

工程對應：

- `CORE_ANATOMY`
- `CORE_FACE_BODY_COHERENCE`
- `CORE_PROPORTION`
- `buildPoseGuidance()`

落地方式：

- 將臉身一致性、頭肩比、脖子與軀幹支撐獨立成前段核心
- `prop` / `comp` 也被要求服從臉部可讀性

狀態：

- `已落地`

### 7. Role / beauty / luxury / goddess keywords are style only

核心規範要求：

- 所有這類詞只能描述風格，不得取代真人身份

工程對應：

- `TPLS.char` 中性化
- `sanitizePromptText()`
- `sanitizeCreativeField()`
- anti-pattern rules

落地方式：

- `char` 不再寫 `heroine`、`beauty` 類人物原型詞
- 高風險欄位用 safer replacement 壓制

狀態：

- `已落地`

### 8. VISUAL REALISM PRIORITY

核心規範要求：

- 最終畫面應像真實攝影
- 不要 AI 美顏模板或假人感

工程對應：

- `CORE_REALISM`
- 安全鏡頭選單
- 安全燈光選單
- 安全氛圍選單

落地方式：

- 已移除或降權高風險廣角、電影預告、低調暗光、仙氣縹緲等路徑
- 預設主幹收斂到更穩的焦段與畫面語言

狀態：

- `已落地`

### 9. CATEGORY-SPECIFIC VISUAL LOCKS

核心規範要求：

- 某些分類有特別視覺限制
- 例如魅魔不得有角與尾巴

工程對應：

- 類別特例規則
- `TPLS`
- 分類對應妝容與補充文句

狀態：

- `已落地`

建議：

- 未來若再增加分類特例，應集中寫成 category rule map，不要散落在多處文字裡

## 現行 prompt engine 的正式主順序

目前實際工程，應以以下主順序為準：

1. `face_lock_core`
2. `pose_coherence_core`
3. `proportion_core`
4. `makeup_safety_core`
5. `anatomy_safety_core`
6. `character_style_block`
7. `costume_block`
8. `scene_block`
9. `lighting_block`
10. `camera_block`
11. `negative_prompt_block`

對應到目前程式時，前 5 層屬於固定核心；後 6 層屬於可變模組。

## 核心規範尚未完全工程化的部分

以下內容目前仍偏「理念或操作層」，尚未完全變成程式強制：

1. 必須先有上傳照片
2. 所有資料來源自動分級為 `approved / legacy / blocked`
3. 所有風格卡自動附帶 `risk_flags`
4. 以機器規則完整掃描 `風格範例.md` 的全量高風險詞

## 建議下一步

若要把規範與工程再對齊一層，最值得做的是：

1. 建立 `風格範例` lint / validator
2. 建立 `legacy` 與 `approved` 的資料分級制度
3. 把 category-specific 規則集中到單一 mapping
4. 把核心規範中的高層 flow，補註為「理念順序」，避免與 engine 順序混淆

## 最終原則

核心規範的責任是定義底線。

工程的責任是把底線拆成：

- 固定 prompt 核心
- 可驗證的資料欄位
- 可清洗的高風險詞
- 可維護的模組邏輯

只要兩者分工清楚，後續擴充風格卡、分類與場景時，就不容易再把系統拉回「場景很強、但真人身份漂掉」的舊模式。
