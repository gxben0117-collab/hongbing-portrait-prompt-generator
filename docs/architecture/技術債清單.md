# 技術債清單

## 高優先

### 1. `index.html` 資料量過大

症狀：

- 全量 `CATS` 直接內嵌
- 單檔接近大型資料庫

風險：

- 修改困難
- merge 衝突機率高
- 人工查找成本高

### 2. `core.js` 責任過重

症狀：

- 同時承擔規則、資料、狀態、渲染與輸出

風險：

- 任一修改都容易產生連動副作用

### 3. `dist/` 不是正式建置流程產物

症狀：

- 現況偏手動同步

風險：

- 發佈內容可能不完整
- `output` / `dist` / 主工程之間容易不一致

## 中優先

### 4. 工具腳本零散

- 已有 `reorder_cats.py`
- 但缺統一工程腳本入口

### 5. 文件缺工程治理層

- 有歷史紀錄
- 缺架構與維護規則

### 6. `requirements.txt` 為空

- 表示 Python 工具層尚未正式化

## 低優先

### 7. `__pycache__` 與 `.venv` 在 repo 內

目前不危險刪除，但後續應透過 `.gitignore` 與規範明確治理。
